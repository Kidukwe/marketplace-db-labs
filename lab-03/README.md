# Лабораторная №3 — многотабличные запросы и аналитические представления

Работа выполняется на существующей схеме `public` из ЛР1 и данных ЛР2.
Таблицы не пересоздаются, строки не удаляются и не обновляются.
Создаются или заменяются только два представления с префиксом `lr3_`.

## Запуск в DBeaver

1. Открой `lab-03/all.sql` через «Редактор SQL → Загрузить SQL скрипт».
2. В верхней панели выбери подключение `marketplace-local`, базу `marketplace`, схему `public`. Во вкладке не должно быть `<none>`.
3. Выполни «Редактор SQL → Выполнить SQL скрипт» целиком. Для одного запроса поставь курсор внутрь него и используй ⌘ Enter.
4. В панели вывода должно появиться «Проверки лабораторной №3 пройдены». Результаты SELECT открываются в отдельных вкладках.
5. Для защиты сохрани результаты Q01–Q11 или скриншоты с текстом запроса и таблицей результатов.

При ошибке внутри блока создания VIEW выполни `ROLLBACK;`, исправь причину и повтори запуск.
Если старый файл `queries.sql` уже открыт в DBeaver, перечитай его с диска, чтобы видеть последнюю версию. Не перезаписывай локальными старыми правками новый файл.

## Файлы

| Файл | Назначение |
|---|---|
| `all.sql` | Один готовый скрипт: queries + views + verify |
| `queries.sql` | Q01–Q09: JOIN, агрегаты, подзапросы, CTE и рекурсия |
| `views.sql` | Два VIEW и обращения Q10–Q11 к ним |
| `verify.sql` | Проверки состава и сумм отчётов без изменения данных |
| `explanation.md` | Разбор каждой реализации и типичных ошибок |
| `defense.md` | Ответы на все десять контрольных вопросов |
| `report.md` | Отчёт: цель, требования и фактическая проверка |
| `tests/edge_cases.sql` | Проверка граничных случаев в тестовой БД с откатом |

Используй либо `all.sql`, либо три исходных SQL-файла по порядку. Двойной запуск безопасен для данных, но не нужен.
`all.sql` собран из трёх исходников. После редактирования исходников его следует пересобрать.

## Соответствие методичке (с. 25–26)

| Пункт | Реализация |
|---|---|
| 1. INNER JOIN минимум трёх таблиц | Q01 |
| 2. LEFT JOIN для строк без соответствия | Q02 |
| 3. Количество товаров и средняя цена по категориям | Q03 |
| 4. Фильтрация групп HAVING | Q04 |
| 5. Скалярный подзапрос, IN и EXISTS | Q05, Q06, Q07 |
| 6. Обычный и рекурсивный CTE | Q08, Q09 |
| 7. Минимум два VIEW с обращениями | V01/V02, Q10/Q11 |

Q03 улучшен относительно первого учебного варианта: теперь показывает и пустые категории. Их количество товаров равно нулю, средняя цена — NULL. Написанный вместе вариант с INNER JOIN сохранён в Q04 с HAVING.

## Проверка

Полный и повторный запуск выполнены в отдельной базе PostgreSQL 17 на данных `lab-01/seed.sql` + `lab-02/seed.sql`. Пройдены проверки `verify.sql` и `tests/edge_cases.sql`. Пользовательская база при этой проверке не изменялась.

Тестовая база не содержит дополнительных 1005 товаров из прежних ручных упражнений. Поэтому её количества отличаются от скриншотов твоей базы — это ожидаемо. Точные результаты приведены в `report.md`.
