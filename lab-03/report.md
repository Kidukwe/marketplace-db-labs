# Отчёт по лабораторной работе №3

**Дисциплина:** математические основы баз данных.

**Тема:** многотабличные запросы и аналитические представления.

**Выполнил:** Дикарев Кирилл.

**СУБД:** PostgreSQL 17. Клиент: DBeaver.

**Дата проверки:** 29 октября 2026 года.

## Цель

Научиться получать связанные данные из нескольких таблиц, вычислять агрегаты по группам, использовать подзапросы и CTE, обходить дерево категорий и сохранять типовые отчёты в VIEW.

## Исходная база

Используется схема public лабораторной №1 и заполнение лабораторной №2. Основные связи: products.category_id → categories.id; products.seller_id → sellers.id; reviews.product_id → products.id; order_items.product_id → products.id; payments.order_id → orders.id. Иерархия категорий задаётся categories.parent_id → categories.id.

SQL ЛР3 не создаёт таблицы, не удаляет и не обновляет строки. Создаются два обычных представления с именами lr3_product_catalog и lr3_seller_report.

## Выполненные требования

| Требование | Реализация и назначение |
|---|---|
| INNER JOIN не менее трёх таблиц | Q01: каталог с категорией и продавцом |
| LEFT JOIN без соответствий | Q02: товары без отзывов |
| Группировка и агрегаты | Q03: количество товаров и средняя цена каждой категории, включая пустые |
| HAVING | Q04: категории с количеством товаров больше 100 |
| Скалярный подзапрос | Q05: товары дороже общей средней цены |
| Подзапрос IN | Q06: товары из категорий с префиксом ЛР2: |
| EXISTS, корреляция | Q07: продавцы, у которых есть товары |
| CTE | Q08: стоимость оплаченных позиций по продавцам, по шагам |
| Рекурсивный CTE | Q09: обход дерева категорий от корней |
| Два VIEW и обращения | V01/V02 и Q10/Q11: каталог и отчёт по продавцам |

Полные тексты находятся в queries.sql и views.sql; единый запускаемый файл — all.sql. Построчное по смыслу объяснение каждого блока — explanation.md.

## Результаты проверки

Проверка проведена в отдельной временной базе на той же схеме PostgreSQL 17. Загружены только воспроизводимые lab-01/seed.sql и lab-02/seed.sql: 1201 товар, 1201 заказ, 8 категорий и 2 продавца. Дополнительные ручные упражнения из рабочей базы в этот набор не переносились.

| Запрос | Фактически получено в тестовой базе |
|---|---|
| Q01 | 1201 строка каталога |
| Q02 | 1050 товаров без отзывов |
| Q03 | 8 категорий, в том числе пустые |
| Q04 | 5 категорий с количеством больше 100; по 240 товаров в каждой |
| Q05 | 601 товар дороже общей средней цены |
| Q06 | 1200 товаров из категорий ЛР2: |
| Q07 | 2 продавца с товарами |
| Q08 | 2 строки оплаченных продаж |
| Q09 | 8 узлов дерева категорий |
| Q10 | 20 самых дорогих активных товаров |
| Q11 | 2 строки отчёта по продавцам |

Оплаченные продажи в Q08 и Q11:

| Магазин | Товаров | Оплаченных заказов | Единиц продано | Стоимость оплаченных позиций |
|---|---:|---:|---:|---:|
| Tech Store | 1 | 1 | 1 | 59 990,00 |
| ЛР2 Магазин | 1200 | 900 | 2700 | 68 850 000,00 |

Для расчёта учитываются позиции заказов с payments.status = 'completed'; цена берётся из order_items.unit_price. Прибыль, комиссии и частичные возвраты не моделируются.

В рабочей базе учащегося скриншотами отдельно подтверждены LEFT JOIN и группировка с HAVING: 7 непустых категорий, количества 506, 500 и пять групп по 240. Все прошли порог 100. Эти числа отличаются от тестовых из-за дополнительных товаров, созданных вручную ранее. Выполнение остальных новых запросов в рабочей базе предстоит продемонстрировать после запуска all.sql.

## Корректность и повторный запуск

Полный all.sql и его повторный запуск прошли без ошибок. verify.sql подтвердил:

- каталог возвращает по одной строке на товар;
- отчёт возвращает по одной строке на продавца;
- число товаров каждого продавца совпадает с исходной таблицей;
- общая сумма оплаченных продаж совпадает со стоимостью оплаченных позиций;
- поиск отсутствующих отзывов через LEFT JOIN совпадает с NOT EXISTS.

Отдельный тест tests/edge_cases.sql создавал фикстуры внутри транзакции и завершился ROLLBACK. Проверены:

- продавец без товаров и продаж: нулевые показатели;
- пустая категория: 0 товаров и NULL средней цены;
- товар с двумя отзывами и товар без отзывов;
- завершённая и незавершённая оплата;
- историческая цена позиции 125 при текущей цене товара 100: сумма двух единиц равна 250;
- категория-внук на глубине 2;
- отсутствие размножения товаров в отчёте от соединений.

Вывод проверок: «Проверки лабораторной №3 пройдены» и «Граничные случаи ЛР3 пройдены». Рабочая база пользователя при автоматической проверке не изменялась.

## Вывод

Реализованы все семь требований технического задания: JOIN, агрегаты и HAVING, три вида подзапросов, обычный и рекурсивный CTE, два представления и обращения к ним. Получен повторно запускаемый скрипт на существующей схеме. Разбор и ответы на контрольные вопросы подготовлены отдельно; самостоятельное понимание новых тем требуется закрепить перед защитой.
