# Лабораторная №4 — оконные функции и аналитика данных

Требования: методичка МОБД, с. 27–29. Используются существующие таблицы public из ЛР1 и данные ЛР2; наличие представлений ЛР3 не требуется. Все запросы ЛР4 только читают данные. Новые таблицы, VIEW и строки не создаются.

## Запуск в DBeaver

1. Открой `lab-04/all.sql` через «Редактор SQL → Загрузить SQL скрипт».
2. Выбери подключение `marketplace-local`, базу `marketplace`, схему `public`.
3. Выполни весь SQL-скрипт. Для отдельного блока поставь курсор в его текст и нажми ⌘ Enter.
4. Просмотри вкладки Q01–Q08 и панель вывода. Ожидаемое сообщение — «Проверки лабораторной №4 пройдены».

Либо запусти `queries.sql`, затем `verify.sql`. `all.sql` содержит эти два файла последовательно. После изменения исходников его нужно пересобрать.

## Определения показателей

- Продажами считаем позиции заказов, для которых платёж имеет статус `completed`. Сумма — `quantity * unit_price`; используется цена покупки, а не текущая цена товара.
- День — дата **создания заказа** в `Europe/Moscow`. Это аналитика оплаченных заказов по дню оформления, а не денежных поступлений по paid_at. Правило выбрано явно и совпадает с примером методички по created_at.
- Q03/Q05 заполняют нулями даты между первой и последней датой оплаченных заказов. Если оплаченных позиций нет, календарь и результат пусты. За пределами этого диапазона дни не добавляются.
- Q04 показывает пары категория–продавец с оплаченными продажами. Продавцы без продаж и категории без продаж отсутствуют; доля внутри каждой представленной категории в сумме равна 1. Округлённые проценты могут дать 99,99 или 100,01.
- Топ-3 означает не более трёх **товаров**, а не все товары с тремя лучшими уникальными ценами. Равные цены разрешаются по id для ROW_NUMBER. В RANK/DENSE_RANK id не входит в порядок окна: иначе равные цены перестали бы быть равными рангами.

## Файлы

- `queries.sql` и `all.sql` — реализация и единый запуск.
- `verify.sql` — проверки размеров результатов, долей, итоговой суммы и равенства двух способов.
- `tests/edge_cases.sql` — откатываемые фикстуры для отдельной тестовой базы.
- `explanation.md` — объяснение каждого запроса.
- `defense.md` — ответы на 10 контрольных вопросов методички.
- `report.md` — цель, результаты и протокол проверки.

Полный и повторный запуск проверены в отдельной PostgreSQL 17; рабочая marketplace при тестировании не изменялась. Ветка — `lab/04-window-functions`. Word-отчёт: [Лабораторная работа №4](../docs/Лабораторная_работа_4_Дикарев_Кирилл.docx).
