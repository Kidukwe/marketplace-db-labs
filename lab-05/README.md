# Лабораторная работа №5 — транзакции и серверная логика

Методичка МОБД, с. 30–34. Используется схема `public` из ЛР1. Скрипты рассчитаны на PostgreSQL 17.

## Запуск в DBeaver

Открой каждый файл через «Редактор SQL → Загрузить SQL скрипт». Проверь подключение и выполни файл целиком командой «Выполнить SQL скрипт». Для демонстрации используй отдельную учебную базу со схемой ЛР1.

| Порядок | Файл | Что показать |
|---|---|---|
| 1 | [install.sql](install.sql) | Функции, триггеры, журнал цен и рейтинг по существующим отзывам |
| 2 | [demo.sql](demo.sql) | Д1. Остаток, число заказов и позиций после `COMMIT`, перед `ROLLBACK` и после него |
| 3 | [verify.sql](verify.sql) | Д2–Д5. Результаты проверок в панели «Вывод» |

Д1 начинает с остатка 5. После фиксации заказа на две единицы ожидается `3 / 1 / 1`. Вторая транзакция оформляет заказ на одну единицу и пробует заказать ещё 99. Исключение перехватывается во вложенном блоке, чтобы скрипт дошёл до явного `ROLLBACK`. Перед откатом ожидается `2 / 2 / 2`, после отката снова `3 / 1 / 1`. Полный запуск удаляет зафиксированные учебные строки в конце. При прерывании после первого `COMMIT` они могут остаться в отдельной учебной базе.

Д2–Д5 используют собственные временные данные в обычных таблицах и откатывают их в конце. Последовательности идентификаторов могут продвинуться. При неожиданной ошибке выполни `ROLLBACK;` перед повтором. Если Д1 прервался, для нового запуска открой новую сессию в чистой учебной базе.

## Соответствие заданию

- **Д1** — явные `BEGIN`, `COMMIT` и `ROLLBACK`, намеренная нехватка товара и сравнение состояния.
- **Д2** — `place_order` оформляет один товар в заданном количестве. Один условный `UPDATE` проверяет и уменьшает остаток под блокировкой строки. Цена покупки сохраняется в позиции заказа. Функция возвращает ID заказа, вызывающая транзакция управляет фиксацией.
- **Д3** — `seller_revenue` считает выручку оплаченных заказов по количеству и цене покупки. Период по времени создания заказа включает нижнюю границу и исключает верхнюю. При отсутствии продаж результат равен нулю.
- **Д4** — `AFTER UPDATE OF price` записывает старую и новую цену, время и роль БД. Повторное присваивание той же цены обходится без записи.
- **Д5** — `AFTER INSERT/UPDATE/DELETE` на отзывах обновляет сумму и количество оценок. Хранимый вычисляемый столбец `rating` делит сумму на количество с округлением до двух знаков. Без отзывов результат `NULL`.

В базе уместны правила, которые должны соблюдаться всеми клиентами: целостность остатков и заказа, аудит и согласованность производных данных. Приложение отвечает за корзину и интерфейс, интеграцию с платёжным сервисом, уведомления и выбор сценария повторной попытки после конфликта транзакций. Ограничение этой учебной функции — одна позиция на заказ.
