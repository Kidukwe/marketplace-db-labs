# Лабораторная работа №2

Базовые SQL-запросы и фильтрация данных.

## Цель и задание

Освоить наполнение связанных таблиц PostgreSQL, выборку столбцов,
устранение дубликатов, фильтрацию, сортировку и постраничный вывод.
По заданию пособия (стр. 21–22) необходимо наполнить все таблицы согласованными
данными, внести не менее 1000 строк в товары и заказы, применить DISTINCT
с псевдонимами, AND/OR со скобками, BETWEEN, IN, LIKE или ILIKE, IS NULL,
сортировку по двум столбцам в разных направлениях и LIMIT/OFFSET.
Для каждого запроса нужны текст, назначение и фрагмент результата.

## Использование результата первой работы

Все 13 таблиц уже созданы первой лабораторной в схеме public базы marketplace.
Вторая работа использует их непосредственно. В скриптах второй лабораторной
нет CREATE TABLE, CREATE SCHEMA, ALTER, DROP, TRUNCATE, DELETE или UPDATE.
Структура не дублируется, существующие строки сохраняются.

## Наполнение

Добавляется отдельная учебная партия с префиксом ЛР2 в названиях товаров
и выделенными email продавца и покупателя. generate_series формирует 1200 товаров,
CASE и арифметика задают разные цены, категории, активность и описания с NULL.
Цены повторяются для демонстрации DISTINCT и дополнительного ключа сортировки.

Новые строки добавляются во все 13 таблиц. У каждого из 1200 новых заказов две
разные позиции, в которых сохраняется цена товара на момент наполнения.
900 заказов имеют платежи с суммами, совпадающими со стоимостью позиций,
600 — доставки на адрес покупателя, 300 — отзывы о купленных товарах.
Добавляются отсутствующие записи складского остатка, включая товары из
предыдущих упражнений; уже существующие остатки не меняются.

Внешние ключи получают фактические id: родители находятся по email,
имени магазина, категории и меткам партии. Новый id заказа получается
через RETURNING. Никаких предположений о начале последовательностей нет.
Вспомогательный блок DO с циклом используется только как генератор связанных
записей и не создаёт хранимые функции или новые объекты схемы.

ON CONFLICT DO NOTHING и проверки NOT EXISTS позволяют повторять наполнение
без добавления дубликатов партии. Проверки меток без уникальных ограничений
рассчитаны на последовательный учебный запуск без конкурентных вставок.
Даты фиксированы, наполнение выполняется в транзакции.

## Запросы и результаты

Ниже приведены тексты и результаты, проверенные на PostgreSQL 17 в отдельной
тестовой базе. До запуска воспроизведены данные первой лабораторной и ручные
упражнения: 1006 товаров и один заказ. Поэтому получены 2206 товаров и 1201 заказ.
В другой базе конкретные id и общие количества могут отличаться.
Q01 считает все строки, Q02–Q12 выбирают учебную партию по префиксу ЛР2.

### Q01 Количество строк во всех 13 таблицах (включая старые данные).

```sql
SELECT 'users' AS table_name, COUNT(*) AS row_count FROM public.users
UNION ALL SELECT 'sellers', COUNT(*) FROM public.sellers
UNION ALL SELECT 'categories', COUNT(*) FROM public.categories
UNION ALL SELECT 'products', COUNT(*) FROM public.products
UNION ALL SELECT 'stock', COUNT(*) FROM public.stock
UNION ALL SELECT 'carts', COUNT(*) FROM public.carts
UNION ALL SELECT 'cart_items', COUNT(*) FROM public.cart_items
UNION ALL SELECT 'addresses', COUNT(*) FROM public.addresses
UNION ALL SELECT 'orders', COUNT(*) FROM public.orders
UNION ALL SELECT 'order_items', COUNT(*) FROM public.order_items
UNION ALL SELECT 'payments', COUNT(*) FROM public.payments
UNION ALL SELECT 'deliveries', COUNT(*) FROM public.deliveries
UNION ALL SELECT 'reviews', COUNT(*) FROM public.reviews
ORDER BY table_name;
```

После воспроизведения первой лабораторной, пяти пробных и тысячи ранее добавленных товаров: users — 4, sellers — 2, categories — 8, products — 2206, stock — 2206, carts — 2, cart_items — 4, addresses — 2, orders — 1201, order_items — 2401, payments — 901, deliveries — 601, reviews — 302.

### Q02 DISTINCT и псевдонимы: уникальные сочетания цены и активности товаров.

```sql
SELECT DISTINCT price AS product_price, is_active AS active
FROM public.products
WHERE title LIKE 'ЛР2 %'
ORDER BY product_price ASC, active ASC;
```

Возвращено 100 уникальных пар. Начало: `(500.00, false)`, `(1000.00, true)`, `(1500.00, true)`. DISTINCT устраняет повторы всей выбранной строки. Уникальный id намеренно исключён.

### Q03 AND, OR и скобки: активные недорогие смартфоны или дорогие ноутбуки.

```sql
SELECT id, title, price, is_active
FROM public.products
WHERE is_active
  AND ((title LIKE 'ЛР2 Смартфон №%' AND price <= 5000)
       OR (title LIKE 'ЛР2 Ноутбук №%' AND price >= 40000))
ORDER BY id
LIMIT 10;
```

Начало: `(1012, ЛР2 Смартфон №5, 3000.00, true)`, `(1088, ЛР2 Ноутбук №81, 41000.00, true)`. Условие активности применяется к обеим альтернативам благодаря скобкам.

### Q04 BETWEEN включает обе границы: товары от 1000 до 2000 включительно.

```sql
SELECT id, title, price
FROM public.products
WHERE title LIKE 'ЛР2 %' AND price BETWEEN 1000 AND 2000
ORDER BY price ASC, id ASC
LIMIT 10;
```

Начало: `(1008, ЛР2 Ноутбук №1, 1000.00)`, `(1108, ЛР2 Ноутбук №101, 1000.00)`. Без LIMIT диапазону соответствуют 36 строк с ценами 1000, 1500 и 2000. Обе границы включены.

### Q05 IN: товары с одной из перечисленных цен.

```sql
SELECT id, title, price
FROM public.products
WHERE title LIKE 'ЛР2 %' AND price IN (500, 1000, 1500)
ORDER BY id
LIMIT 10;
```

Начало: `(1007, ЛР2 Смартфон №0, 500.00)`, `(1008, ЛР2 Ноутбук №1, 1000.00)`, `(1009, ЛР2 Книга №2, 1500.00)`. IN выбирает одну из перечисленных цен.

### Q06 ILIKE: поиск по части названия без учёта регистра.

```sql
SELECT id, title, price
FROM public.products
WHERE title ILIKE 'ЛР2 %СМАРТФОН%'
ORDER BY id
LIMIT 10;
```

Начало: `(1007, ЛР2 Смартфон №0, 500.00)`, `(1012, ЛР2 Смартфон №5, 3000.00)`. ILIKE выполняет поиск без учёта регистра, % допускает произвольную последовательность символов.

### Q07 LIKE: символ _ соответствует ровно одному символу.

```sql
SELECT id, title
FROM public.products
WHERE title LIKE 'ЛР2 Книга №_'
ORDER BY id;
```

Две строки: `(1009, ЛР2 Книга №2)`, `(1014, ЛР2 Книга №7)`. Символ _ допускает ровно один символ после №, поэтому ЛР2 Книга №12 не подходит.

### Q08 IS NULL: товары без описания. COALESCE оформляет результат для чтения.

```sql
SELECT id, title, COALESCE(description, 'Нет описания') AS description
FROM public.products
WHERE title LIKE 'ЛР2 %' AND description IS NULL
ORDER BY id
LIMIT 10;
```

Начало: `(1007, ЛР2 Смартфон №0, Нет описания)`, `(1014, ЛР2 Книга №7, Нет описания)`. Всего 172 товара партии без описания. COALESCE меняет только результат выборки, в таблице остаётся NULL.

### Q09 Два столбца в разных направлениях: цена убывает, id возрастает.

```sql
SELECT id, title, price
FROM public.products
WHERE title LIKE 'ЛР2 %'
ORDER BY price DESC, id ASC
LIMIT 10;
```

Начало: `(1106, ЛР2 Чехол №99, 50000.00)`, `(1206, ЛР2 Чехол №199, 50000.00)`. Сначала цена убывает, при равной цене id возрастает.

### Q10 Первая страница по 10 товаров.

```sql
SELECT id, title, price
FROM public.products
WHERE title LIKE 'ЛР2 %'
ORDER BY price DESC, id ASC
LIMIT 10 OFFSET 0;
```

Первая страница: id 1106, 1206, 1306, 1406, 1506, 1606, 1706, 1806, 1906, 2006. Начальная строка: `(1106, ЛР2 Чехол №99, 50000.00)`.

### Q11 Вторая страница: пропускаем первые 10 товаров в том же порядке.

```sql
SELECT id, title, price
FROM public.products
WHERE title LIKE 'ЛР2 %'
ORDER BY price DESC, id ASC
LIMIT 10 OFFSET 10;
```

Начало: `(2106, ЛР2 Чехол №1099, 50000.00)`, `(2206, ЛР2 Чехол №1199, 50000.00)`, `(1105, ЛР2 Куртка №98, 49500.00)`. Пересечений с первой страницей нет. Для страницы k и размера s смещение равно (k − 1) × s. При параллельных изменениях данных страницы могут сдвигаться.

### Q12 Положение NULL при сортировке, дополнительный пример к вопросу 7.

```sql
SELECT id, title, description
FROM public.products
WHERE title LIKE 'ЛР2 %'
ORDER BY description ASC NULLS FIRST, id ASC
LIMIT 10;
```

Начало: `(1007, ЛР2 Смартфон №0, NULL)`, `(1014, ЛР2 Книга №7, NULL)`. NULLS FIRST размещает отсутствующие описания перед заполненными.

## Проверка

Общий скрипт выполнен с остановкой при первой ошибке (ON_ERROR_STOP=1)
на существующих таблицах public в тестовой базе PostgreSQL 17.
Проверены наполненность всех таблиц, размер партии, позиции заказов,
наличие остатков, суммы платежей, принадлежность адресов,
распределение NULL и активности, диапазон цен и непересечение страниц.

Контрольные суммы всех исходных строк до и после наполнения совпали.
Повторный запуск также прошёл, контрольные суммы содержимого всех 13 таблиц
после первого и второго запуска совпали: дубликаты не добавились.
Последовательности IDENTITY могут пропускать значения из-за ON CONFLICT;
это нормально, непрерывность id не требуется.
Рабочая база marketplace при проверке не изменялась.
