# Лабораторная работа №2

Базовые SQL-запросы и фильтрация данных в существующей базе маркетплейса.

## Что выполняется

Таблицы уже созданы первой лабораторной в `public`. Вторая работа добавляет
согласованные тестовые данные и выполняет запросы. В её SQL нет создания,
удаления или изменения структуры таблиц, создания схем, очистки таблиц,
удаления или обновления существующих строк.

Новая партия содержит 1200 товаров и 1200 заказов с двумя позициями в каждом.
Названия учебных товаров начинаются с `ЛР2 `, пользователи имеют email
`seller@lr2.example.test` и `buyer@lr2.example.test`. Это позволяет отличать
партию от предыдущих упражнений и повторять запуск без накопления дубликатов.
Дополнительно создаются связанные корзина, адрес, платежи, доставки, отзывы.
Для всех товаров добавляются недостающие записи остатков.

## Запуск в DBeaver

1. Подключиться к базе `marketplace`, содержащей таблицы первой лабораторной.
2. Создать новую SQL-вкладку для этого подключения.
3. Выбрать «Редактор SQL → Загрузить SQL скрипт» и указать `lab-02/all.sql`.
4. Выполнить весь файл через «Редактор SQL → Выполнить SQL скрипт».
5. Просмотреть результаты Q01–Q12. Повторять только выборки удобно из `queries.sql`.

Если ранее загружена старая копия скрипта, повторно загрузить актуальный файл:
загрузка в SQL-вкладку не обязательно связывает её содержимое с файлом на диске.
В актуальном файле первая строка: «ЛР2. Наполнение и запросы для таблиц public
из лабораторной №1».

При ошибке внутри транзакции выполнить `ROLLBACK;`, устранить причину и повторить
полный запуск. Генератор рассчитан на последовательный учебный запуск без
одновременного редактирования партии ЛР2. Его метки зарезервированы для этой работы.
Если ранее была создана отдельная схема `lab02`, этот вариант её не использует
и не удаляет: все запросы явно направлены на `public`.

## Файлы

| Файл | Назначение |
|---|---|
| `all.sql` | Общий файл для DBeaver: наполнение, проверки и запросы |
| `seed.sql` | Добавление данных в существующие таблицы, в транзакции |
| `queries.sql` | Q01–Q12: количества, выборки и фильтрация |
| `verify.sql` | Дополнительные проверки связанных данных и результатов |
| `report.md` | Требования, решения, тексты запросов и проверенные результаты |
| `defense.md` | Все 10 контрольных вопросов с объяснениями |

`all.sql` — последовательное объединение `seed.sql`, `verify.sql`, `queries.sql`.
После изменения исходных файлов нужно обновлять и общий файл.
Запускать `seed.sql` отдельно, а затем `all.sql` не требуется: наполнение одно.

## Как устроено наполнение

Простые данные формируются через `INSERT ... SELECT` и `generate_series`.
Существующие ключи находятся по уникальным email, имени магазина и категории.
Фактические id товаров находятся по зарезервированным учебным названиям.
При создании заказа `RETURNING id` получает назначенный PostgreSQL идентификатор.
Для повтора заказ определяется по учебному покупателю и фиксированной дате.
Идентификаторы не вычисляются из числа генератора и последовательности не сбрасываются.

`ON CONFLICT DO NOTHING` используется там, где уникальность обеспечена схемой.
`WHERE NOT EXISTS` используется для учебных меток без отдельного ограничения
уникальности. Поэтому это воспроизводимый последовательный генератор,
а не механизм конкурентного оформления заказов.
`DO` и цикл служат только вспомогательному наполнению связанных таблиц.
Хранимые функции, триггеры и новая структура БД во второй работе не создаются.

На тестовой базе с исходными 1006 товарами и одним заказом получилось
2206 товаров и 1201 заказ. Итоговые общие количества зависят от старых данных.
Выборки Q02–Q12 ограничены партией ЛР2 для воспроизводимости примеров.

## Git

Работа находится в ветке `lab/02-basic-queries`. Для сохранения после просмотра:

```sh
git add lab-02
git commit -m "feat: complete lab 02 SQL queries and test data"
git push -u origin lab/02-basic-queries
```

После этого можно открыть pull request в `main` и выполнить merge после сдачи.
Независимое изменение `.env.example` не включается командой `git add lab-02`.
В Git сохраняются скрипты и отчёт, а не содержимое базы в Docker.
