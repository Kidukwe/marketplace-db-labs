## 1. Из каких секций состоит команда SELECT и в каком порядке они логически выполняются?

Порядок записи: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY,
LIMIT/OFFSET. Не все секции обязательны.

Упрощённый логический порядок: FROM → WHERE → GROUP BY → HAVING →
вычисление SELECT → DISTINCT → ORDER BY → OFFSET/LIMIT.
Это модель смысла запроса, а не обязательная последовательность физических
операций: оптимизатор может выбрать другой план с тем же результатом.

Псевдоним из SELECT доступен в ORDER BY, но не в WHERE того же уровня.
Например, Q02 сортирует по псевдонимам product_price и active.

## 2. Почему в промышленных запросах не рекомендуется использовать SELECT *?

Он возвращает все столбцы, в том числе ненужные. Это может увеличить объём
передаваемых данных, раскрыть лишние поля и изменить структуру результата при
добавлении столбца в таблицу. Явный список делает назначение запроса понятнее.
Это рекомендация, а не запрет; ускорение зависит от конкретного запроса и плана.
COUNT(*) — отдельная конструкция для подсчёта строк, она не выдаёт все столбцы.

## 3. Для чего предназначена секция WHERE и как в ней комбинируются условия?

WHERE отбирает строки: остаются только те, для которых условие равно TRUE.
FALSE и UNKNOWN исключаются. AND требует истинности обоих условий,
OR — хотя бы одного, NOT отрицает логическое значение.
Приоритет: NOT, затем AND, затем OR. Скобки явно задают группировку.

В Q03 активность требуется и для недорогих смартфонов, и для дорогих ноутбуков:
`is_active AND (условие_смартфона OR условие_ноутбука)`.

## 4. Чем предикаты BETWEEN и IN отличаются от записи тех же условий через операторы сравнения и OR?

BETWEEN задаёт включённый с двух сторон диапазон:
`price BETWEEN 1000 AND 2000` эквивалентно
`price >= 1000 AND price <= 2000`.
IN проверяет принадлежность списку:
`price IN (500, 1000, 1500)` эквивалентно
`price = 500 OR price = 1000 OR price = 1500`.
Они короче выражают намерение; сами по себе не гарантируют более быстрое
выполнение. При NULL сохраняются правила трёхзначной логики. В частности,
NULL внутри списка может привести к UNKNOWN при отсутствии совпадения;
это особенно важно для NOT IN.

## 5. Как работает оператор LIKE и что означают символы % и _ в шаблоне?

LIKE сопоставляет строку с шаблоном целиком. `%` означает любое количество
символов, включая ноль; `_` — ровно один символ.
`LIKE 'ЛР2 Книга №_'` выбирает ЛР2 Книга №2, но не ЛР2 Книга №12.
`ILIKE 'ЛР2 %СМАРТФОН%'` ищет подстроку без учёта регистра; обработка регистра
зависит от локали. Для буквальных `%` и `_` нужно экранирование.

## 6. Что такое трёхзначная логика и почему нельзя проверять значение на NULL оператором «=»?

NULL обозначает неизвестное или отсутствующее значение. Сравнения с NULL
обычными операторами, включая `NULL = NULL`, дают UNKNOWN, а не TRUE.
Поэтому используются IS NULL и IS NOT NULL.
Логические значения SQL: TRUE, FALSE и UNKNOWN.
Например, TRUE AND UNKNOWN даёт UNKNOWN, FALSE AND UNKNOWN даёт FALSE,
TRUE OR UNKNOWN даёт TRUE, а NOT UNKNOWN остаётся UNKNOWN.

В Q08 отсутствие описания проверяется через IS NULL.
COALESCE возвращает первое значение, отличное от NULL, и подставляет текст
только в результат запроса. NULL, пустая строка, ноль и текст 'NULL' различаются.

## 7. Что делает секция ORDER BY и как задать сортировку по убыванию и положение NULL?

ORDER BY задаёт порядок строк результата. ASC означает возрастание,
DESC — убывание; направление задаётся для каждого выражения отдельно.
В Q09 `ORDER BY price DESC, id ASC`: сначала дороже, при равной цене —
меньший id. Последующие ключи используются только при равенстве предыдущих.
NULLS FIRST и NULLS LAST явно задают положение NULL.
В PostgreSQL по умолчанию ASC использует NULLS LAST, DESC — NULLS FIRST.
Без ORDER BY порядок строк не гарантирован.

## 8. Для чего служат LIMIT и OFFSET и как с их помощью организовать постраничный вывод?

LIMIT ограничивает число строк, OFFSET пропускает указанное количество строк.
При размере страницы 10 первая страница — LIMIT 10 OFFSET 0,
вторая — LIMIT 10 OFFSET 10. Для страницы k: OFFSET `(k - 1) * 10`.
Необходим одинаковый однозначный ORDER BY: в Q10–Q11 равенства цены
разрешены уникальным id. При изменениях данных между запросами состав страниц
может сдвигаться. Большой OFFSET дорог: пропускаемые строки также обрабатываются.

## 9. Что делает ключевое слово DISTINCT?

Убирает повторяющиеся строки результата по всем выбранным выражениям вместе.
В Q02 остаются уникальные пары (price, is_active), всего 100 строк.
Каждая такая пара повторяется у нескольких товаров партии ЛР2.
Если включить уникальный id, каждая строка уже будет различной.
При устранении дубликатов NULL считаются одинаковыми.
DISTINCT не изменяет исходную таблицу и не гарантирует сортировку.

## 10. Как сгенерировать большой объём тестовых данных средствами PostgreSQL?

generate_series создаёт набор значений. Для целых чисел границы включаются:
от 0 до 1199 получается 1200 строк при шаге 1.
INSERT ... SELECT записывает вычисленные на их основе значения.
В нашем генераторе `%` распределяет категории и продавцов, `||` создаёт
названия, CASE задаёт NULL и статусы, арифметика формирует цены.
Можно использовать random(), но для воспроизводимости здесь выбраны формулы.

Сначала заполняются родительские таблицы, затем дочерние. Нужно соблюдать
внешние ключи, уникальность и CHECK. id не обязан совпадать с числом генератора.
В этой работе последовательности не сбрасываются: реальные id находятся
по ключам и меткам партии, а новый id заказа получается через RETURNING.
ON CONFLICT и NOT EXISTS позволяют повторять последовательное наполнение
без добавления дубликатов учебной партии.
